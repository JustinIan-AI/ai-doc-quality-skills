# test-doc-quality-review

## 职责

评审测试文档是否足以验证 PRD/设计，而非执行测试。

## 输入

- 测试文档
- PRD 与/或设计（用于覆盖映射；缺失则标注限制）

## 检查清单

1. 每条 P0/P1 需求是否至少有一条正向用例。
2. 异常/边界/权限否定是否覆盖设计中的失败模式。
3. 前置数据、环境、清理是否可执行。
4. 断言是否可判定（禁止无阈值的「体验良好」「性能尚可」）。
5. 是否与设计 API/状态机字段对齐（参数、错误码、状态名）。
6. 非功能：负载、超时、并发、降级是否有对应场景。
7. 回归范围与冒烟集是否标明。

维度权重见 score-config `dimensions.test`。

## 输出

- findings bundle
- 可选：覆盖缺口表（需求 ID → 缺失用例类型）

## 禁止

- 把「建议补用例」写成已存在的用例
- 无映射依据时宣称 100% 覆盖

## Definition of Done

- 覆盖与可判定性均有结论
- 缺口可映射到需求或设计锚点
