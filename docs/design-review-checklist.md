# 企业用 Design Review 检查清单

版本：`design-checklist-1.0.0`  
适用：AI 生成的概要设计、详细设计、架构说明、数据设计、API 设计文档。

每条 finding 输出固定字段：

```text
严重度 | 证据位置 | 问题类型 | 影响 | 修改建议 | 是否阻断
```

严重度：`P0` 阻断 / `P1` 高 / `P2` 中 / `P3` 低。

---

## A. 与需求的一致性（权重建议 20%）

1. 每个 PRD 需求 ID 是否在设计中有对应实现路径（无孤儿需求）。
2. 设计是否引入 PRD 未授权的范围（范围蔓延）。
3. 验收标准是否可映射到可观察的系统设计行为。
4. 非功能需求（性能、可用性、合规）是否落到具体机制，而非口号。

**默认 P0 候选**：核心需求无设计映射；关键业务规则在设计中被静默删除。

## B. 架构与边界（15%）

1. 系统边界、外部依赖、信任边界是否明确。
2. 模块职责是否单一、依赖方向是否合理（有无循环依赖说明）。
3. 同步/异步边界、最终一致性假设是否写清。
4. 关键路径是否有失败域隔离与降级策略。

## C. 数据设计（15%）

1. 核心实体、主键、唯一约束、生命周期是否完整。
2. 状态机是否闭合（合法迁移、非法迁移、终态）。
3. 事务边界、幂等键、去重策略是否定义。
4. 软删/归档、审计字段、历史数据策略是否有。
5. 敏感数据分级与脱敏/加密落点是否明确。

**默认 P0 候选**：状态机不闭合；核心写路径无幂等定义。

## D. API / 契约（15%）

1. 接口语义、错误码、幂等、分页/过滤约定是否一致。
2. 版本策略与兼容性破坏是否说明。
3. 请求/响应示例是否覆盖主路径与典型错误。
4. 与前端/调用方的契约是否可测试（schema 或等价描述）。

## E. 权限与安全（10%）

1. 认证方式、会话/令牌生命周期。
2. 授权模型（RBAC/ABAC）与资源级校验点。
3. 越权、水平权限、批量接口风险是否被点名。
4. 日志中是否避免明文敏感信息。

**默认 P0 候选**：多角色系统但无授权模型。

## F. 异常、并发与可靠性（10%）

1. 超时、重试、熔断、补偿是否定义且不互相矛盾。
2. 并发写冲突策略（乐观锁/悲观锁/队列串行化）。
3. 部分失败、重复提交、乱序消息的处理。
4. 回滚与数据修复路径是否可操作。

## G. 可观测与运维（5%）

1. 关键指标、日志字段、链路追踪标识是否定义。
2. 告警条件与 on-call 可行动性。
3. 配置变更、特性开关、灰度发布是否有设计位。

## H. 可实现性与可测试性（10%）

1. 是否依赖未确认的第三方能力或未立项基础设施。
2. 是否存在无法在测试环境复现的设计假设。
3. 是否给出可验证的设计验收点（不仅是「实现后自测」）。

---

## 门禁规则

- 任一「需求无设计映射」「状态机不闭合」「多角色无权限模型」「核心写路径无幂等」→ 默认 P0。
- 仅文案完善、图示美观但上述缺失 → 不得 `APPROVE`。
- 结论枚举：`APPROVE` | `APPROVE_WITH_RISKS` | `NEEDS_WORK` | `REJECT`。

本清单由 `design-quality-review` Skill 加载；变更必须升版本号。
